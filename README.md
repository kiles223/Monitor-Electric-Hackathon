# Monitor-Electric-Hackathon

Пример обезличенной модели - https://disk.yandex.ru/d/nczMGKsFXKcvQQ

Обезличивание моделей энергосистем в формате CIM RDF/XML (МЭК 61970) с сохранением структуры, связей между объектами и числовых параметров.

Заменяет персональные данные и реальные названия (абоненты, сотрудники, адреса, подстанции, линии, серийные номера) синтетическими значениями. Результат детерминирован: при одной соли и одном входе выходной файл побайтно одинаков.

## Возможности

- **Потоковая обработка.** Файл читается построчно, память не зависит от его размера. На файле 966 МБ (9,76 млн строк) обработка заняла около 5,5 минут при пиковой памяти около 280 МБ, процессор один.
- **Детерминированность.** Все замены считаются как HMAC от секретной соли и значения. Коллизии разрешаются перебором, поэтому разные исходные значения не сливаются в одно.
- **Целостность связей.** Идентификаторы объектов (GUID) заменяются одной функцией везде, где встречаются, поэтому ссылки `rdf:resource` остаются рабочими.
- **Все поля с `name`.** Обезличиваются все поля, в названии свойства которых есть `name` (`name`, `aliasName`, `folderName`, `buildingName` и т. д.), а также описания, комментарии, номера и идентификаторы.
- **Бинарные вложения.** Вложения в base64 распознаются по сигнатуре и обрабатываются:
  - ZIP-схемы подстанций (в том числе вложенные архивы): подписи, имена и ссылки на объекты заменяются, изображения внутри схем заменяются заглушкой;
  - XML-вложения (например, описания участков линий);
  - служебные PNG-значки, звуки и двоичные таблицы без текста остаются как есть.
- **Язык подставляемых значений** задаётся в конфигурации. Есть русский, английский и немецкий, любой другой подключается JSON-словарём.
- **Проверка результата** отдельным скриптом `verify.py`.

## Что на что заменяется

| Что | Как |
|---|---|
| ФИО абонентов, сотрудников, ответственных | синтетические ФИО из словаря имён |
| Топонимы и собственные имена в названиях подстанций, линий, измерений, адресов | прилагательные из названий овощей и фруктов; одно слово всегда заменяется одинаково |
| Названия улиц | синтетическая фамилия |
| Номера подстанций и фидеров, серийные и инвентарные номера, ИНН и другие длинные числа | случайные числа той же длины, одно число всегда заменяется одним и тем же |
| Телефоны и email в тексте | случайные цифры, адреса в домене `example.invalid` |
| GUID (`rdf:about`, `rdf:resource`, `mRID`) | детерминированные новые GUID |

Не меняются: структура XML, классы и типы объектов, числовые параметры, напряжения (`110 kV`), технические слова, короткие номера (меньше 3 цифр) и номера опор, справочные системные GUID, ссылки на внешние ресурсы, не связанные с энергообъектами.

## Требования

Python 3.8+ и только стандартная библиотека.

## Запуск

```
python anonymize.py input.xml output.xml --salt "ВАША_СЕКРЕТНАЯ_СОЛЬ"
```

Соль можно передать и переменной окружения `ANON_SALT`. Не публикуйте соль: по ней и исходному файлу результат воспроизводится.

| Параметр | Назначение |
|---|---|
| `--config файл` | файл настроек (по умолчанию `config.json` рядом со скриптом) |
| `--language код` | язык подставляемых значений, переопределяет конфигурацию |
| `--extra-vocab файл` | дополнительные слова для замены, по одному в строке |
| `--stats-out файл` | сохранить статистику работы (время, память, число замен) в JSON |
| `--map-out файл` | таблица соответствий; **содержит исходные данные**, не передавать |

## Конфигурация (`config.json`)

| Параметр | По умолчанию | Описание |
|---|---|---|
| `language` | `auto` | `auto` определяет язык по алфавиту исходного значения; либо код из папки `lexicons/` |
| `lexicon_files` | `[]` | дополнительные файлы словарей |
| `extra_vocab` | `[]` | дополнительные слова для замены |
| `stop_words` | `[]` | слова, которые не заменять |
| `min_digits_prefixed` | `3` | от скольки цифр менять номера после `Sub`, `ПС`, `ТП`, `feeder` |
| `min_digits_global` | `6` | от скольки цифр менять числа в любом тексте |
| `process_blobs` | `true` | обрабатывать бинарные вложения |
| `images` | `blank` | `blank` заменяет изображения в схемах заглушкой, `keep` оставляет |
| `icon_max_pixels` | `65536` | одиночные PNG до этого размера считаются служебными значками |

### Свой язык

Положите JSON-файл в `lexicons/` (имя файла становится кодом языка) и укажите его в `language`. Формат смотрите в `lexicons/de.json`:

```json
{
  "language": "de",
  "adjectives": ["Apfel", "Birne"],
  "first_names": ["Hans", "Peter"],
  "surnames": ["Mueller", "Schmidt"],
  "patronymics": [],
  "name_format": "{first} {surname}"
}
```

Для уникальности замен нужен достаточно большой словарь: при нехватке слов программа составляет двойные формы и добавляет числовые суффиксы.

## Как это работает

1. **Проход 1.** Собирается словарь собственных имён: слова из названий подстанций, линий, регионов, организаций и адресов (технические слова пропускаются), а также список абонентов.
2. **Проход 2.** Файл читается построчно и переписывается. Листовые значения полей обезличиваются по правилам выше, вложения разбираются и пересобираются, GUID заменяются.

## Проверка результата

```
python verify.py input.xml output.xml --salt "ВАША_СОЛЬ"
```

Для больших файлов этапы можно запускать отдельно: `--stage orig`, `result`, `leak`, `blobs`, `names`.

Скрипт проверяет:

1. совпадение числа строк, порядка тегов и числа объектов по классам;
2. целостность ссылок и неизменность графа связей;
3. сохранение числа уникальных имён в каждом классе;
4. что имена абонентов, сотрудников, адресов, подстанций и линий не остались прежними, длины чисел в названиях сохранены и одно число всегда заменяется одним и тем же;
5. отсутствие исходных названий и имён внутри вложений и замену изображений в схемах;
6. что имя объекта, входящее в имя ссылающегося на него объекта, остаётся его частью.

## Ограничения

- Собственные имена находятся автоматически только в названиях подстанций, линий, организаций и адресов. Слова, встречающиеся лишь в других местах, добавляйте через `--extra-vocab` или `extra_vocab`. Результат стоит просмотреть на оставшиеся топонимы.
- Растровые изображения в схемах заменяются заглушкой целиком: текст на них не распознаётся.
- Загрузка модели в реляционную БД не реализована, вход и выход в формате XML.
- Прямое сравнение статистических распределений (нагрузки, число ТП на фидер) не выполняется: числовые параметры не меняются.
- Вложения неизвестных форматов остаются без изменений.
